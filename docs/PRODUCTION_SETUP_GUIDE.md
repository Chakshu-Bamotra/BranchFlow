## Step 1: Firebase Cloud Project Creation

1. Open the [Firebase Console](https://console.firebase.google.com/) and sign in with your Google account.
2. Click **"Add project"** and name it `branchflow-production`.
3. Choose whether to enable Google Analytics (recommended for production monitoring) and click **Create Project**.
4. Inside your new project:
   - **Authentication**: Go to *Build ➔ Authentication ➔ Get Started*. In the *Sign-in method* tab, enable **Email/Password**.
   - **Cloud Firestore**: Go to *Build ➔ Firestore Database ➔ Create Database*.
     - Choose a region close to your users (e.g., `asia-south1` for India or `us-central1` for US).
     - Select **Production Mode** (your rules will be deployed in Step 3).
   - **Cloud Storage**: Go to *Build ➔ Storage ➔ Get Started*. Select the default bucket location and click Done.

## Step 2: Connecting Flutter to Live Firebase

FlutterFire CLI automatically provisions Android, iOS, and Web platform configurations directly into your app.

### 1. Install CLI Tools
If not already installed on your computer:
```bash
# Install Firebase CLI
npm install -g firebase-tools

# Login to Firebase
firebase login

# Install FlutterFire CLI
dart pub global activate flutterfire_cli
```

### 2. Run FlutterFire Configure
From your workspace root (`c:\Users\hp\BranchFlow`):
```bash
flutterfire configure --project=branchflow-production
```
- Select the platforms you want to support: `android`, `ios`, `web`, `windows`.
- FlutterFire will automatically generate [`lib/firebase_options.dart`](file:///c:/Users/hp/BranchFlow/lib/firebase_options.dart) and place `google-services.json` in `android/app/`.

### 3. Activate Production Mode in `main.dart`
In [`lib/main.dart`](file:///c:/Users/hp/BranchFlow/lib/main.dart), ensure `Firebase.initializeApp` receives the options:
```dart
import 'firebase_options.dart'; // Generated by flutterfire

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );
  runApp(const BranchFlowApp());
}
```

## Step 3: Deploying Firestore Security Rules & Indexes

BranchFlow already includes production rules and composite index specifications versioned in your repository:
- [`firestore.rules`](file:///c:/Users/hp/BranchFlow/firestore.rules) — Restricts loans so only librarians can mark returns; members can only read their own records.
- [`storage.rules`](file:///c:/Users/hp/BranchFlow/storage.rules) — Limits file sizes to 5MB and enforces image MIME types.
- [`firestore.indexes.json`](file:///c:/Users/hp/BranchFlow/firestore.indexes.json) — Multi-field ordering indexes for loans and transit.
- [`firebase.json`](file:///c:/Users/hp/BranchFlow/firebase.json) — Configuration connecting rules and indexes to the Firebase CLI.

### Deploy in One Command:
```bash
firebase deploy --only firestore,storage
```

Verify in the Firebase Console:
- *Firestore ➔ Rules*: You will see the deployed rules active.
- *Firestore ➔ Indexes*: The composite indexes will be created automatically.

## Step 4: Seeding Live Initial Data

Your live Firestore database will start empty. BranchFlow includes an in-app 1-click database seeder!

### Method A: In-App 1-Click Seeder
1. Run the app: `flutter run -d windows` (or on your device).
2. On the **Dashboard**, look at the top app bar.
3. Tap the **Cloud Upload icon** (`Sync / Seed Live Cloud Data`).
4. BranchFlow will batch-write:
   - 4 community branches (`Central`, `Westside`, `Oakridge`, `Northgate`)
   - 8 catalog books with ISBNs and barcodes
   - Seeded loan records with penalty avoidances
   - Staged transit items
5. Open your [Firebase Console](https://console.firebase.google.com/) ➔ *Firestore Database* and watch the documents appear in real time!

## Step 5: Cloud Messaging & Push Notifications (FCM)

For production library operations, notifications keep members informed about due dates and return clearances:

1. Add `firebase_messaging` to `pubspec.yaml`:
   ```bash
   flutter pub add firebase_messaging
   ```
2. Request notification permissions on mobile startup:
   ```dart
   final messaging = FirebaseMessaging.instance;
   final settings = await messaging.requestPermission(
     alert: true,
     badge: true,
     sound: true,
   );
   ```
3. When a member returns a book to another branch, use Cloud Functions or FCM to send a push notification:
   > *"Return Verified: Your loan for 'Clean Code' was received at Westside Library. Fines frozen at $0.00."*

## Step 6: Production Release Signing & Store Builds

### Android Release Build (Google Play Store)

1. **Generate Upload Keystore**:
   ```powershell
   keytool -genkey -v -keystore android/app/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```
2. **Create `android/key.properties`**:
   ```properties
   storePassword=your_store_password
   keyPassword=your_key_password
   keyAlias=upload
   storeFile=upload-keystore.jks
   ```
3. **Reference in `android/app/build.gradle`**:
   Ensure `signingConfigs.release` reads `key.properties`.
4. **Build the Production App Bundle (AAB)**:
   ```bash
   flutter build appbundle --release
   ```
   *The optimized bundle will be generated at `build/app/outputs/bundle/release/app-release.aab` ready for upload to Google Play Console.*

---

### iOS Release Build (Apple App Store)

1. Open `ios/Runner.xcworkspace` in Xcode.
2. Select **Runner** in the project navigator ➔ **Signing & Capabilities**.
3. Select your Apple Developer Team and assign a unique Bundle Identifier (`org.branchflow.app`).
4. In terminal:
   ```bash
   flutter build ipa --release
   ```
   *Upload to TestFlight and App Store Connect using Xcode Organizer or `fastlane`.*
